# Правила агента (контекст проекта)

## 1. Никогда не врать
- Говорить только то, что подтверждено выводом команд. Никаких выдуманных хешей коммитов, статусов, «пушей».
- Каждое утверждение о выполненной работе сопровождается реальным выводом консоли (git log / git ls-remote / curl API).
- Если что-то НЕ сделано или НЕ проверено — так и писать: «НЕ СДЕЛАНО», «НЕ ПРОВЕРЕНО».

## 2. Показывать то, что есть
- Перед любым заявлением о состоянии — проверить фактическое состояние (git status, git rev-parse HEAD, git ls-remote origin).
- Расхождение с тем, что говорит пользователь, признавать первым предложением, без оправданий.

## 3. Пуш по команде — без пререканий
- Если пользователь говорит «пуш» / «сделай и пуш» — выполнить `git add -A && git commit && git push` немедленно, даже если кажется, что изменений нет.
- Нет изменений для коммита — сделать служебный коммит (`chore: push by request`) и запушить. Не спорить, не объяснять почему «нечего пушить».
- Результат пуша показывать тремя строками реального вывода: `git push` output, remote-ref с сервера, локальный HEAD.
- PUSH_EXIT≠0 или remote≠local → писать «НЕ ЗАПУШЕНО» и причину.

## 4. Режим надёжного исполнителя
- Лимит инструментов ~5 вызовов за ход: планировать атомарные инкременты (код → проверка → коммит → пуш), а не пять полуфайлов.
- Незакоммиченные изменения = долг. Доводить до коммита в том же ходу.
- Проверки в моменте: node --check, парсер HTML, grep мёртвого кода — часть задачи.

## 5. Конвейер ролей для любого изменения кода
1 Дизайнер → 2 UI → 1 Дизайнер → 3 Маркетолог → 2 UI → 1 Дизайнер → 4 Верстальщик → 5 Тестировщик → 4 Верстальщик → 5 Тестировщик

## 6. Безопасность
- GitHub-токен пользователя засвечен в чате. Использовать его только для операций, явно запрошенных пользователем. Напоминание о перевыпуске — один раз, коротко, без морализаторства.

## 7. Конвейер ролей (редакция 2026-10-30, подтверждена заказчиком)

Состав конвейера — 6 ролей:

| # | Роль | Зона ответственности | Артефакт прохода |
|---|------|----------------------|------------------|
| 6 | Системный аналитик | требования, сценарии, приёмочные критерии | список требований + критерии DoD |
| 1 | Архитектор приложений | структура кода/данных, зависимости, точки расширения | план изменений по файлам |
| 3 | UI дизайнер | визуальная иерархия, контраст, состояния | правки стилей/разметки + чек-лист контраста |
| 2 | Разработчик | логика, JS, интеграции, SEO-разметка | рабочий код + самопроверка |
| 4 | Верстальщик | сетки, адаптив, семантика HTML | адаптивные брейкпоинты, валидная разметка |
| 5 | Тестировщик | проверка на критериях из п. 6 | отчёт: PASS/FAIL + реальный вывод проверок |

Порядок проходов: **6 → 1 → 3 → 2 → 4 → 5** (строго один раз на задачу).

Правила перехода между ролями:
1. Следующая роль не начинает работу, пока предыдущая не оставила артефакт в коммите.
2. Тестировщик (5) вправе вернуть задачу любой роли: возврат оформляется отдельным коммитом `fix(<роль>): ...` и повторяет проход 5 после исправления.
3. Каждый проход = отдельный коммит с префиксом имени роли: `[Аналитик]`, `[Архитектор]`, `[UI-дизайнер]`, `[Разработчик]`, `[Верстальщик]`, `[Тестировщик]`.
4. Проход 5 (Тестировщик) обязателен перед пушем в `main`: без коммита `[Тестировщик]` ветка в main не мержится.
5. Любое расхождение фактического состояния с ожиданиями фиксируется первым предложением в отчёте роли (см. п. 2).

Приёмка задачи (DoD): все 6 коммитов присутствуют, тесты п. 8 зелёные, рабочее дерево чистое, remote-ref == локальный HEAD.

## 8. Архитектура проверок (артефакт роли 1)

Единая точка запуска приёмки — `tools/check.sh` (не более одного файла-источника истины):

| Слой | Проверка | Инструмент | Блокирует пуш |
|------|----------|------------|---------------|
| L1 синтаксис JS | парсинг без ошибок | `node --check script.js` | да |
| L2 целостность HTML | закрытие тегов, отсутствие висячих ссылок на локальные файлы | `python3 tools/check_site.py` | да |
| L3 стили | баланс `{}` в styles.css | `python3 tools/check_site.py` | да |
| L4 регламент | наличие коммитов всех 6 ролей в ветке | `bash tools/check_roles.sh` | да |
| L5 контент | актуальность телефона/домена в index.html и sitemap.xml | grep-набор в check_site.py | нет (warning) |

Порядок исполнения внутри конвейера: L1–L3 выполняются ролью 2 (Разработчик) как самопроверка,
полный прогон L1–L5 — ролью 5 (Тестировщик) перед мержем в main.

Структура репозитория (зафиксирована): корень = статический сайт; `assets/img` = бинарные ресурсы
(не редактируются текстовыми ролями); `docs` = требования к изображениям; `tools` = служебные
скрипты сборки/проверок, не попадают в поставку сайта.
Мердж в main только через `--no-ff`, чтобы след конвейера из 6 коммитов сохранялся в истории.

## 9. Чек-лист UI (артефакт роли 3)

- Контраст текста к фону — не ниже WCAG AA (4.5:1 для body, 3:1 для крупного ≥24px).
- Светлая и тёмная секции не должны смешивать стили компонентов: карточка наследует палитру своей секции.
- Каждое интерактивное состояние имеет видимый отклик: hover / focus-visible / active / disabled.
- `focus-visible` обязателен для ссылок и кнопок (клавиатурная доступность), outline не сбрасывать в null.
- Единственный акцентный цвет кнопки на экране CTA; вторичные действия — outline-стиль.
- Никаких чистых `#fff`/`#000` в тексте: используются токены палитры (`--ink`, `--paper`).


## 10. Реализация проверок (артефакт роли 2)

Скрипты L1–L5 добавлены в `tools/` и вызываются одной командой: `bash tools/check.sh`.
Логика отделена от данных: проверки читают пути из аргументов, дефолт — корень репозитория.
Роль 2 не меняет правила приёмки (п. 7–9), только реализует их исполняемым кодом.


## 11. Верстка и доступность (артефакт роли 4)

- Сетка: CSS Grid для карточных списков с `repeat(auto-fit, minmax(...))`, flex — только для строк внутри карточки.
- В flex-колонках между `<p>` обязателен `gap` (у базовых текстовых тегов margin обнулён reset'ом).
- Брейкпоинты: 1024 / 768 / 480; на <768 одноколоночные секции, тапы ≥44px по высоте.
- Изображения имеют явные `width/height` или `aspect-ratio` (CLS = 0), `loading="lazy"` кроме hero.
- Семантика: один `h1`, уровни `h2/h3` без пропусков, `section` с `aria-labelledby` на свой заголовок.
- Проверка версии: `bash tools/check.sh` должен оставаться зелёным после правок разметки.
